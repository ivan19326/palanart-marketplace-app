# GPT-консультант PALANART

Состояние на 27.10.2026: код и локальные проверки подготовлены; **оплата,
рабочий API-ключ, production backend и реальный ответ GPT не подтверждены**.
В публичной конфигурации `enabled: false`: посетителям не показывается
недействующее окно. База Supabase и существующие аккаунты не изменялись.

## Два разных применения

| Назначение | Возможности и доступ |
| --- | --- |
| Консультант посетителя | Ответы о PALANART, уточнение пожеланий, подбор из публичного снимка каталога, подготовка текста заявки. Реализован интерфейс и серверный запрос OpenAI. Запись заявок и доступ к кабинетам не подключены |
| Помощник разработчика | Исследование кода и логов, воспроизведение ошибки, регрессионный тест, исправление, проверка и публикация. Для PALANART это уже выполняется в Codex. Отдельный агент разработчика внутри сайта не реализован |

Сам API-ключ даёт доступ к модели. Доступ к репозиторию, запуску тестов, логам
или выпуску исправлений требует отдельных инструментов и разрешений. Публичный
чат этих инструментов не получает. Для поиска ошибок и доработок здесь, в Codex,
новая покупка API не требуется; расход API нужен для размещённого консультанта.

## Что подготовлено

- `handler.mjs`: Responses API, серверный ключ, фиксированная модель, ограниченные
  вход/выход, structured JSON, `store: false`, только чтение справочных данных.
- `public-knowledge.json`: снимок двух одобренных публичных карточек из исходников,
  без пользователей, телефонов, паролей или сессий. Свободные даты не известны.
  `node assistant/export-catalog.cjs` обновляет снимок из изолированной памяти,
  не читая реальную пользовательскую базу или localStorage браузера.
- `quota.mjs`: сохраняемый дневной счётчик запросов до обращения к OpenAI, включая
  неудачные обращения. Лимит по умолчанию 100/сутки UTC. Ошибка файла запрещает
  новые обращения. Это **лимит запросов, а не долларовый лимит**.
- `server.mjs`: Node.js 24+, до четырёх параллельных запросов, до восьми запросов
  в минуту с адреса, тело до 16 KB. Не пишет содержание вопросов или ключ в лог.
- Виджет: загрузка, ошибки, повторная попытка, новый диалог, Escape, мобильный
  размер. Текст ответа выводится через `textContent`; кликабельные карточки
  создаются только по известным публичным id. Диалог хранится в памяти вкладки.
- В GitHub Actions добавлены проверки границ доступа и лимитов консультанта.

`store: false` не означает отсутствие любой обработки/хранения на стороне
провайдера. Перед отправкой пользователь видит уведомление о передаче текста
OpenAI и просьбу не отправлять пароли и личные данные.

## Что сделать владельцу для оплаты и ключа

1. Войти в [OpenAI Platform](https://platform.openai.com/), проверить доступность
   API и оплаты для своего аккаунта. Подписка ChatGPT и API имеют отдельные
   настройки биллинга. На [странице Billing](https://platform.openai.com/settings/organization/billing/overview)
   проверить условия и вручную завершить покупку выбранной суммы. Сумма владельцем
   пока не подтверждена, оплату агент не выполнял.
2. Использовать отдельный проект OpenAI для PALANART, настроить доступные в
   аккаунте ограничения расходов и уведомления. Учитывать фактический смысл
   показанных лимитов: дневной счётчик приложения не является денежным бюджетом.
3. На [странице API keys](https://platform.openai.com/api-keys) выпустить отдельный
   серверный ключ и сохранить его как `OPENAI_API_KEY` в секретах выбранного
   backend. Не вставлять ключ в чат, `marketplace_build`, GitHub Pages или Git.
4. Нужен действующий HTTPS backend: существующий сервер с Node.js 24+ и
   постоянным диском либо согласованная адаптация к восстановленному Supabase.
   GitHub Pages публикует только frontend. Новый backend не создаёт пользовательскую
   БД. Подключённого подходящего production backend сейчас не обнаружено.

## Локальная проверка без платного обращения

Из корня репозитория, PowerShell:

```powershell
$env:OPENAI_API_KEY = ''
$env:ASSISTANT_PREVIEW = '1'
$env:ASSISTANT_ORIGINS = 'http://127.0.0.1:8788'
npm run assistant:start
```

Открыть `http://127.0.0.1:8788/preview`. При пустом ключе сервер возвращает 503,
виджет показывает ошибку и сохраняет вопрос для повторной отправки. Ответ GPT
не имитируется. Preview выключен по умолчанию, это не публичный маршрут.

## Порядок запуска

1. После выбора backend задать переменные из `.env.example` через его хранилище
   секретов. Для локального запуска можно использовать игнорируемый
   `assistant/.env.local`, который читает `npm run assistant:start`.
2. Развернуть **один процесс** сервиса с постоянным диском для файла квоты.
   Текущая файловая квота не подходит для нескольких процессов или ephemeral
   serverless-инстансов. При смене архитектуры нужен общий атомарный счётчик;
   изменения существующей БД требуют отдельной проверки и согласования.
3. Настроить TLS на reverse proxy, лимит тела и частоты запросов. По умолчанию
   приложение слушает только `127.0.0.1`. За прокси учитывается его socket IP;
   дополнительные реальные клиентские лимиты настраиваются на доверенном прокси.
   CORS ограничен origin сайта, но сам по себе не является аутентификацией.
4. Проверить `/health` (показывает наличие конфигурации, **не валидность ключа**),
   затем один реальный `POST /v1/chat` с origin сайта и контролируемым вопросом.
   Проверить списание/usage, корректный ответ, ссылку на карточку, лимиты, ошибки,
   отсутствие секретов в браузере. До этого живой GPT считать неподключённым.
5. В `marketplace_build/assistant-config.js` указать точный HTTPS URL `/v1/chat`
   и включить `enabled`. Опубликовать через существующий процесс Pages, обновить
   версию config URL и cache service worker. Повторить тест на основном домене.
   Для отключения достаточно `enabled: false`; данные аккаунтов не затрагиваются.
6. При появлении действующего backend заново проверить справочную информацию
   об авторизации и обновить публичный снимок каталога.

## Проверки

`npm run test:assistant` — восемь проверок настоящего обработчика с тестовым
OpenAI-адаптером и временными файлами: входные роли/лимиты, отсутствие ключа,
CORS, закрытые маршруты, фиксированный запрос, фильтр карточек, ошибки, дневная
квота, параллельные запросы и перезапуск. Вместе с `npm run test:auth` — 28 тестов.
Они не подтверждают доступность аккаунта OpenAI, оплату и качество реальных ответов.

Браузером проверены открытие, отправка без ключа, сохранение текста при ошибке,
разблокировка кнопок и Escape; проверены мобильные размеры. Не выполнен реальный
чат с моделью, так как ключа нет.
